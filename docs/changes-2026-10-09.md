# What changed on 2026-10-09

The client-feedback work of 2026-10-09, in one place: what each change does, how it works, and
where to look. It is all on the `dev` branch. What the clinic asked for, and what is still open,
is in [client-requests.md](client-requests.md).

**At a glance:** one backend change (search), one Docker change (image volume), one seeder
change (demo visits); the rest is frontend. No migrations, no new endpoints. Frontend: 155 test
files, 862 tests, typecheck and lint clean. Backend: all unit, architecture and integration tests
pass.

After pulling, rebuild the API once: `docker compose up -d --build web-api`.

## Patients

- **Search by card number.** The backend patient search also matches the card number. The search
  box says what it searches. *Where:* `GetPatientsQueryHandler`, `PatientFilters`.
- **Age.** Age shows as "3 yrs 2 mo", "7 mo" or "2 wk" everywhere (`formatAge`, which replaced
  `calculateAge`). An **Age** box beside the date of birth fills the date from a number of years;
  picking a date updates the box. The date of birth is still the only stored value.
  *Where:* `patientAge.ts`, `BirthDateField`.
- **Coat colour.** The Color field has a row of common coat colours and name suggestions; the
  value is still plain text, so typing works for anything else. *Where:* `CoatColorField`,
  `shared/domain/coatColors.ts`.

## Patient record

- **Header.** Owner and phone (tap to call) under the animal's name, and the header band tinted by
  species: blue dog, yellow cat, violet bird, green other. The same header is used by Complete
  visit and the visit history window. *Where:* `PatientHeader`, `SPECIES_TINT`, `--species-*`
  tokens, `SlidePanel`'s `headerTint`.
- **Opens where you are.** One component, `PatientRecord`, owns the record with its edit form,
  delete confirmation and visit editing. Patients, Appointments and Reports all render it, so the
  record opens on top of the current page instead of jumping to Patients. The old
  `/patients?patient=` link is gone.
- **Visit history.** The record shows a short visits summary with "Open visit history". That opens
  a wide centred window with the visits in the shared table. Clicking a row opens a read-only
  view of that visit, with charges, images, "Mark as paid" and **Edit**; Edit swaps the view for
  the edit form. *Where:* `VisitsSummary`, `VisitHistory`, `VisitDetailPanel`,
  `PatientCardPanel`.
- **Images only in edit mode.** The visit view only shows and opens images. Adding and removing
  moved to an Images section in the visit's Edit form; those changes save at once, not on Save.
  *Where:* `AttachmentStrip` (`editable`), `ExaminationEditPanel`.

## Visits and the price list

- **Complete visit** shows the patient header with allergies above the form. Before the patient
  has loaded, or for a booking without a patient yet, it shows a plain title with a chip.
- **Therapy and charges** sit in one box in the exam form; the charges editor no longer draws its
  own. *Where:* `ExaminationFields`, `ChargesEditor`.
- **Price list** is no wider than it needs, so prices sit beside the names.
- **Euro rate.** A "Euro rate" tab under Lists holds dinars per euro, set by hand. Once set, the
  price list shows an "In euros" column and the visit total shows its euro value. Like the rest of
  the price list it is mock data in the browser until its backend exists; the endpoints are in
  [the backend proposal](specs/2026-10-05-legacy-features-backend-api.md). *Where:*
  `ExchangeRateTab`, `useExchangeRate`, `formatEuro`.

## Keyboard and readability

- **Tables.** Every clickable table works from the keyboard: Tab to a row, arrows to move, Enter
  to open. In a search box, the down arrow jumps into the table below; up from the first row goes
  back. *Where:* `shared/ui/Table`, `SearchInput`.
- **Shortcuts.** **N** opens "New …" on every page, **/** jumps to search, **P** prints a report.
  Buttons show their key as a small hint. Shortcuts are ignored while typing or with a panel
  open. To add one to a new page, give its main button `shortcut="n"`.
  *Where:* `shared/lib/useShortcut`, `Button`.
- **Text.** Table text is a step larger and the grey text colours are darker, now passing WCAG AA.
  *Where:* `tokens.css`, `Table.module.css`.

## Shared building blocks

- **`CenteredPanel`.** A centred dialog with exactly the side panel's props plus `size`
  (`medium` or `wide`). Use it for any big form or view; switching is a one-word change. Both
  panels share an internal `PanelFrame` (header, body, footer) and one z-index level, so the last
  panel opened always sits on top and dims the rest.

## Backend and Docker

- **Images survive rebuilds.** Visit images are files in the API container; the database keeps
  only their path. A Compose volume, `api-storage`, now holds them, and the Dockerfile creates the
  folder so the non-root API user can write to it. Images uploaded before this are gone and
  answer 404. The Render test server still loses images on each deploy; that needs S3-style
  storage later.
- **Demo visits.** The demo seeder adds three past visits for Charlie on fixed dates and skips
  them if they already exist.

## Removed

`calculateAge` (replaced by `formatAge`), the `/patients?patient=` link, `ExaminationCard` (the
visit history table replaced it), and the charges editor's own box and heading.

## Good to know

- **Line endings.** The checkout uses CRLF and Prettier writes LF. Format only the files you
  changed; formatting a whole folder makes every file in it show as modified.
- **Busy machine.** A few long form tests can time out at 15 s when a dev server runs alongside
  the test suite. They pass on a quiet run.
- **One unpaid rule.** A visit owes money only when its cost is above zero and it is not paid
  (`isUnpaid` in the examinations feature). Visit history, the visit view and the reports all use
  it, and the daily report shows "No cost" instead of "Unpaid" for visits without a cost.
- **What a payment refreshes.** Paying, editing or adding a visit refreshes the patients' visit
  lists (`examinationKeys.patients`), not the image downloads, so images are not fetched again.
- **Euro rate rule.** The 0 to 1000 limit lives with the price rules in the price list feature
  (`rateError`), so swapping the mock store for the real API does not touch the UI.
- **Shared-code changes** are also listed at the end of
  [the hardening document](specs/2026-09-21-frontend-hardening-before-scheduling.md).
