# Appointments tab — implementation record

Status: implemented 2026-08-04. Design in
`docs/superpowers/specs/2026-08-04-zakazano-design.md`.

Originally a fourteen-task plan with full code inline. The code is in the repository now, so
that detail has been removed and only the decisions remain.

At the time this feature was called *Zakazano*. It is now `features/appointments` — see "Stale
references" below.

## What was built

The appointment scheduling tab: day, week and month calendar views, side panels for viewing,
editing and creating an appointment, and RTG attachments. Every appointment is mandatorily
linked to a patient.

Order: shared date helpers, widening the patients barrel, types and domain date helpers, mock
data and API, the appointment chip, calendar toolbar, the three views, detail and form panels,
the page, routing, then cross-wiring the dashboard stats and navigation links.

## Decisions worth knowing

**No new `shared/ui` components.** The whole tab was built from what the previous phase already
provided. The calendar grids are hand-rolled CSS.

**`date-fns` was added for calendar maths only**, not for formatting date-only strings.

**Two deliberate cross-feature imports.** Patients imports `getAppointments` from appointments
for the dashboard stat cards; appointments imports `getPatients` and `SPECIES_EMOJI` from
patients to display the linked animal. Both go through each feature's public `index.ts`, and
both are safe despite looking circular: ES module cycles only break when a binding is read
during top-level evaluation, and every usage here is deferred inside a function body or render.

**Date-only strings never touch `new Date(iso)` or `.toISOString()`.** Everything goes through
`parseDateOnly` / `formatDateOnly` / `todayIso`, or compares zero-padded strings directly. This
avoids the timezone shifts that come from treating a calendar date as an instant — the same
class of bug that later caused a 500 on patient birth dates.

**No tests, no backend** — same as the previous phase.
